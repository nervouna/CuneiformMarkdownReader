# 极简 macOS Markdown 预览器设计

版本：V0.1  
日期：2026-05-26  
状态：Draft  

## 目标

构建一个极简 macOS Markdown 预览 app，用于快速查看 AI 生成的大段 Markdown 文件。应用启动后的主要界面只显示渲染后的文档内容，不提供编辑区、文件树、侧边栏或内容区工具栏。

MVP 必须解决三个核心问题：

- 双击或通过 Finder 打开 Markdown 文件时，应用能作为默认打开程序使用。
- 用户可以通过拖拽和系统文件选择器打开 Markdown 文件。
- 渲染排版遵循 macOS 阅读体验和长文阅读最佳实践。

## 非目标

MVP 不做以下能力：

- Markdown 编辑。
- 多标签页、文件管理、项目工作区或文档库。
- 云同步、历史记录、全文搜索。
- 内置浏览器导航。
- 插件系统或主题市场。
- Mermaid、数学公式、图表等高级扩展。

## 用户体验

### 主窗口

主窗口内容区仅显示当前 Markdown 文件的渲染结果。空状态可以显示极简提示，例如“打开或拖入 Markdown 文件”，但在文件渲染后必须让位给纯阅读视图。

窗口使用 macOS 标准标题栏和系统菜单。内容区不放工具栏。打开、重新载入、字号调整和外观设置通过系统菜单和快捷键完成。

### 文件打开方式

应用支持以下入口：

- Finder 双击 `.md` 或 `.markdown` 文件。
- 设置为 `.md` 或 `.markdown` 的默认打开程序后，从 Finder 直接打开。
- `File > Open...` 打开系统文件选择器。
- 将 Markdown 文件拖拽到应用窗口。

如果用户打开不支持的文件类型，应用应显示明确错误，不静默失败。

### 阅读排版

默认排版以长文阅读为中心：

- 正文使用系统字体或适合 macOS 阅读的默认字体。
- 内容最大行宽受控，避免全屏时行长过长。
- 标题层级、段落间距、列表缩进和引用块保持清晰。
- 代码块使用等宽字体，并支持横向滚动。
- 表格在窄窗口中可横向滚动。
- 图片自适应内容宽度，保留原始宽高比例。
- 深色模式、浅色模式和跟随系统外观应保持足够对比度。

## Markdown 能力

MVP 支持 GitHub Flavored Markdown 的常见能力：

- 标题、段落、强调、删除线。
- 有序列表、无序列表、嵌套列表。
- 任务列表。
- 表格。
- 引用块。
- 行内代码和围栏代码块。
- 代码高亮。
- 本地相对图片。
- 普通链接。

链接点击交给系统默认浏览器打开。应用不在内部提供浏览器导航能力。

## 安全策略

Markdown 渲染必须默认安全。MVP 对原始 HTML 采用转义显示策略，不保留 HTML 标签语义。这样可以避免脚本、事件属性、iframe、object、embed、远程脚本和其他主动内容进入预览环境。

资源与链接策略：

| 输入类型 | MVP 策略 |
| --- | --- |
| Markdown 标准文本、列表、表格、任务列表、代码块 | 允许渲染 |
| Raw HTML | 转义为可见文本 |
| `http` / `https` 链接 | 点击后交给系统默认浏览器 |
| `mailto` 链接 | 点击后交给系统处理 |
| `javascript:` 链接 | 禁止打开 |
| `file:` 链接 | 禁止打开 |
| 其他未知 scheme | 禁止打开 |
| 本地相对图片 | 仅允许当前 Markdown 文件所在目录及其子目录内的文件 |
| 远程图片 | MVP 禁止加载 |
| `data:` 图片 | MVP 禁止加载 |
| SVG 图片 | MVP 禁止加载 |

本地相对图片路径必须先做 URL 解码、标准化和符号链接解析，再判断解析后的真实路径是否仍位于 Markdown 文件所在目录内。包含 `../`、URL 编码绕过、符号链接跳出目录或解析失败的资源一律不加载。

错误信息不能泄露敏感本地环境变量、密钥或不必要的路径细节。

## 技术方案

推荐使用原生 macOS 技术栈：

- SwiftUI 负责应用生命周期、窗口、菜单和基础状态管理。
- AppKit 在需要时补足文件打开、拖拽、默认程序关联和 `WKWebView` 集成。
- `WKWebView` 负责显示由 Markdown 转换出的安全 HTML。
- Markdown parser 负责将 Markdown 转换为 HTML，并启用 GFM 常见扩展。
- HTML template 与 CSS 定义阅读排版、深浅色主题、代码块和表格样式。

不采用 Flutter 或 Electron 作为 MVP 技术路线。原因是默认文件关联、macOS 菜单、文档打开生命周期、沙盒访问和窗口行为在原生技术栈下更直接，也更容易符合 macOS 设计规范。

## 架构边界

### App Shell

负责 macOS 应用生命周期、菜单命令、窗口创建、外观设置和文件打开事件分发。它不直接处理 Markdown 解析细节。

### File Intake

负责接收来自 Finder、文件选择器和拖拽的文件 URL，验证文件类型，管理安全访问，并读取 Markdown 内容。

### Markdown Rendering

负责 Markdown 到安全 HTML 的转换。该模块应集中处理 GFM 扩展、HTML 安全策略、代码高亮输入和图片路径解析。

### Preview View

负责把 HTML 注入 `WKWebView`，处理链接点击、滚动行为、重新载入和错误展示。

### Preferences

MVP 可以保存最少偏好：字号缩放和外观模式。该能力低于文件打开、渲染、安全和默认程序支持优先级；如果实现排期需要收敛，偏好持久化可以延后，菜单动作仍应在当前会话生效。

## 状态与错误

应用至少包含以下状态：

- Empty：未打开文件。
- Loading：正在读取或渲染。
- Rendered：已显示文档。
- Error：文件不支持、读取失败、渲染失败或资源访问受限。

错误展示应简洁且可恢复。用户可以通过 `Open...` 或拖拽另一个文件继续使用。

## 默认文件程序支持

应用包需要声明 `.md` 和 `.markdown` 文档类型，使用户能在 Finder 中将其设置为默认打开程序。实现应支持通过系统文档打开事件接收文件，而不是只依赖命令行参数。

## 测试与验证

MVP 完成前至少验证：

- Markdown parser 单元测试覆盖 GFM、表格、任务列表、代码块、相对图片和 HTML 安全策略。
- File Intake 单元测试覆盖支持类型、不支持类型和不存在文件。
- 安全测试覆盖 raw HTML 转义、`javascript:` 链接拦截、`file:` 链接拦截、远程图片拦截、`data:` 图片拦截、SVG 图片拦截、`../` 路径拦截、URL 编码路径绕过和符号链接跳出目录。
- 链接行为测试覆盖 `http`、`https` 和 `mailto` 交给系统处理，且 `WKWebView` 不进行内部导航。
- UI 或集成验证覆盖 `Open...`、拖拽打开和 Finder 打开事件。
- 手动视觉检查覆盖浅色、深色、窄窗口、宽窗口、长文、表格、代码块和大图片。
- 应用包声明包含 `.md` 和 `.markdown` 文档类型。

## 验收标准

MVP 可被接受的条件：

- 用户能将应用设置为 `.md` 文件默认程序，并通过 Finder 打开 Markdown 文件。
- 用户能将应用设置为 `.markdown` 文件默认程序，并通过 Finder 打开 Markdown 文件。
- 打开文件后，内容区仅显示渲染后的 Markdown，不出现编辑器或多余工具界面。
- 拖拽和 `Open...` 均可切换当前文档。
- 标题、段落、强调、删除线、列表、任务列表、表格、引用块、行内代码、围栏代码块、代码高亮、本地相对图片可正确显示。
- 链接点击在系统默认浏览器中打开。
- 深浅色外观下排版清晰，长文阅读不拥挤。
- 不执行 Markdown 中的脚本或主动内容。
